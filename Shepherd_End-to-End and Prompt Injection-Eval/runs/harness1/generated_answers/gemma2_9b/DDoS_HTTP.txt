Reference Answer:
Important service indicators include high CPU usage on web servers, API gateways, reverse proxies, or application backends; exhausted worker pools, connection pools, database sessions, memory, file descriptors, or queue capacity; increased latency for legitimate administrative actions or device control operations; failed device check-ins, delayed telemetry processing, or missed control commands; and health checks failing on application routes while lower-level network connectivity remains available.

Incident Only Answer:
During a DDoS_HTTP incident, focus on these service-health indicators for your IoT infrastructure:

* **Network throughput and latency:** Monitor for significant drops in bandwidth and increased response times to identify the impact of the attack on network performance.
* **Web server load and resource utilization:** Track CPU, memory, and disk usage on web servers hosting your IoT applications to detect overload and potential service disruptions. 
* **Application availability and uptime:** Ensure that critical IoT services remain accessible and responsive despite the DDoS attack. Implement monitoring tools to track application status and alert on downtime.
* **Endpoint connectivity and health:** Monitor the status of connected IoT devices and their ability to communicate with the network and web servers.
