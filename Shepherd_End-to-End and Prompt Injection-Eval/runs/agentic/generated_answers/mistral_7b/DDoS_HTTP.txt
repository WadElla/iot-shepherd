Question:
What traffic indicators should be examined to confirm an HTTP-based denial-of-service attack against IoT services?

Reference Answer:
The administrator should examine whether there is a sharp increase in HTTP requests to a small number of endpoints or routes, many requests with similar methods, paths, user agents, headers, or payload sizes, and repeated requests that trigger authentication, dynamic page generation, search, database lookup, device status polling, or firmware download. The administrator should also check for high request rates from many sources, a single local segment, compromised devices, or unexpected network locations, along with incomplete requests, abnormal connection resets, server errors, timeouts, or HTTP 4xx and 5xx responses.

With Context Answer:
To confirm an HTTP-based denial-of-service (DoS) attack against IoT services, the following traffic indicators should be examined:
1. Identify top requested paths, methods, response codes, user agents, request sizes, and error rates.
2. Compare traffic from legitimate devices with suspicious sources to avoid blocking required device communications.
3. Determine whether the attack uses many external sources, a small number of local devices, compromised internal endpoints, or spoofed-looking headers.
4. Check whether backend failures were caused by authentication, database queries, firmware downloads, API polling, or application worker exhaustion.
5. Record which controls reduced latency, restored service health, or decreased backend load.

Incident Only Answer:
To confirm an HTTP-based Denial-of-Service (DoS) attack against IoT services, the following traffic indicators should be examined:

1. Anomalous Traffic Volume: A significant increase in HTTP traffic volume compared to normal levels, especially if it exceeds network capacity or resource limits on the targeted IoT devices.
2. Request Rate Spikes: Sudden spikes in request rates, particularly GET requests, which are common in DoS attacks like DDoS_HTTP.
3. High Frequency of Short Requests: A high number of short HTTP requests with a small time interval between them can indicate a DoS attack.
4. Unusual User Agent Strings: Examining user agent strings for patterns that do not match normal client behavior can help identify potential attackers.
5. Inconsistent IP Addresses: Multiple, often non-human-like, IP addresses generating requests can be an indicator of a DoS attack.
6. HTTP Methods or Headers Abuse: Analyzing the use of unusual HTTP methods (e.g., HEAD, OPTIONS) or headers (e.g., malformed or unexpected values) could point to an attack.
7. Response Time Outliers: Responses with unusually long or short latency times compared to normal network behavior may indicate a DoS attack.
8. Geographical Disparity: Inbound traffic from unexpected geographic locations, especially when combined with other indicators, can suggest a DoS attack.
9. Unusual Patterns in HTTP Cookies or Sessions: Investigating patterns of cookies and sessions that do not conform to normal user behavior may help identify potential attacks.
10. Correlation with Other Attack Indicators: Cross-referencing indicators, such as those listed above, can strengthen evidence of a DDoS_HTTP attack against IoT services.
