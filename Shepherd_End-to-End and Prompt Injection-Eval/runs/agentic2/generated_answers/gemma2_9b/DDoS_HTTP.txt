Question:
What traffic indicators should be examined to confirm an HTTP-based denial-of-service attack against IoT services?

Reference Answer:
The administrator should examine whether there is a sharp increase in HTTP requests to a small number of endpoints or routes, many requests with similar methods, paths, user agents, headers, or payload sizes, and repeated requests that trigger authentication, dynamic page generation, search, database lookup, device status polling, or firmware download. The administrator should also check for high request rates from many sources, a single local segment, compromised devices, or unexpected network locations, along with incomplete requests, abnormal connection resets, server errors, timeouts, or HTTP 4xx and 5xx responses.

With Context Answer:
DDoS HTTP detection should combine traffic volume, request patterns, application logs, resource utilization, and service health. Administrators should identify top requested paths, methods, response codes, user agents, request sizes, and error rates.  Compare traffic from legitimate devices with suspicious sources to avoid blocking required device communications. Determine whether the attack uses many external sources, a small number of local devices, compromised internal endpoints, or spoofed-looking headers. Check whether backend failures were caused by authentication, database queries, firmware downloads, API polling, or application worker exhaustion.

Incident Only Answer:
Focus on examining traffic originating from  `192.168.0.128` towards `192.168.0.170` as this pair exhibits the highest volume of DDoS_HTTP attacks (313 samples). Look for unusually high request rates, a disproportionate number of small GET requests targeting specific resources, and potentially malformed or oversized HTTP headers.  Additionally, examine traffic patterns to identify potential botnets by looking for synchronized bursts of activity from multiple sources.

Device data ingestion, administrator dashboards, firmware distribution, and authentication should be separated into independently protected services where feasible. The administrator should reduce the cost of unauthenticated requests, design degraded modes that preserve critical device control, test DDoS playbooks, and document controls that can be activated without vendor approval.
