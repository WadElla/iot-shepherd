Logs, configuration snapshots, packet captures, device state, and file hashes should be preserved before major remediation changes.

3. Disable compromised credentials, administrative accounts, service accounts, API tokens, and remote access sessions that may be involved in the backdoor activity.

Question:
What persistence mechanisms should be inspected before concluding that a Backdoor has been removed?

Reference Answer:
The administrator should review startup services, cron jobs, init scripts, systemd units, vendor extension hooks, plugin directories, and scheduled tasks. Firmware and configuration checksums should be compared against a trusted baseline or vendor image. The administrator should also search for unknown binaries, writable directories used for execution, modified web directories, added keys, and hidden configuration files. A backdoor should not be considered removed until persistence mechanisms and compromised credentials are addressed.

With Context Answer:
To conclude that a Backdoor has been effectively removed, it is necessary to inspect and address the following persistence mechanisms:

1. Unknown binaries: Search for unknown or suspicious executable files on affected endpoints that may have been implanted by the attacker for continued access.
2. Writable directories used for execution: Assess any writable directories on affected endpoints that could potentially be used to execute malicious code.
3. Modified web directories: Look for altered web directories (e.g., HTTP, FTP) that might contain hidden configuration files or other backdoor artifacts.
4. Added keys: Investigate any new SSH keys, API tokens, or certificates added to the affected endpoints by the attacker.
5. Hidden configuration files: Examine hidden or obscure configuration files on affected devices for evidence of backdoor functionality.
6. Scheduled tasks: Review and remove any scheduled tasks that were added by the attacker as a means of maintaining persistence.
7. Altered group memberships: Assess changes to user or system group memberships that may have been manipulated to grant unauthorized access.
8. Remote access tools: Look for unauthorized remote access tools (e.g., TeamViewer, AnyDesk) installed on affected endpoints as a persistence mechanism.

Incident Only Answer:
To ensure the removal of the Backdoor, you should inspect the following persistence mechanisms:

1. Startup Files and Registries: Check for any suspicious files or registry entries that are set to launch at system startup, which could be associated with the backdoor. This includes executables, scripts, or services.

2. Network Connections: Investigate any permanent connections (Permanent Internet Connections - PIC) or scheduled tasks that allow the backdoor to communicate with its command and control (C&C) server.

3. System Services: Examine system services for any new or modified services related to the Backdoor, as they may start automatically during system boot and allow the malware to maintain persistence.

4. Host-based Intrusion Prevention Systems (HIPS): Ensure that any rules created by the backdoor have been removed from HIPS configurations, which could allow the malware to reinstall itself or execute commands.

5. Accounts and Privileges: Review for any newly created accounts or modified user account permissions that may be used by the backdoor to gain unauthorized access to your network.

6. System Libraries and DLLs: Inspect for any rogue Dynamic Link Libraries (DLL) or system library files that are being loaded by the Backdoor for persistence, especially those in critical paths such as %System32%, %AppData%, or %Temp%.

7. Firewall Rules: Check if any firewall rules have been added or modified to allow traffic associated with the backdoor, enabling it to evade detection and maintain a connection to its C&C server.
